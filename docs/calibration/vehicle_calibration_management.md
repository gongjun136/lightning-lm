# 车辆标定档案与验收

不同车辆的标定按车辆和版本归档，场地地图单独归档。运行前生成完整 YAML，程序仍读取现有格式，无需为了选择车辆修改 C++。

## 档案结构

```text
F:/datasets/SANY/
  vehicles/<vehicle_id>/
    vehicle.yaml
    calibrations/<calibration_id>/
      extrinsics.yaml
      metadata.yaml
  sites/<site_id>/
    raw/<rig>/mapping|relocalization/<bag>/
    derived/lightning-lm/
      experiments/<run_id>/
      maps/<map_version>/
```

`vehicle.yaml` 记录稳定车辆编号、VIN/域控 ID、主雷达、各雷达 ID/位置/序列号/话题。IP 可重复使用，不能作为车辆身份。`metadata.yaml` 记录版本、车辆归属、来源、提供时间、实际标定时间、矩阵约定、单位和 `extrinsics.yaml` 的 SHA-256。未知字段保留 null，提供时间不能代替标定时间。

本批数据临时档案为 `new_vehicle_20260922`，版本为 `user_provided_20261010_v1`，VIN、域控 ID、雷达序列号等待确认。这个名称只标识这次采集，不是已核实的车辆编号。确认身份后关联正式编号，并保留旧标识或别名，避免既往实验来源失效。

标定矩阵文件按版本冻结。修改、重新标定、拆装雷达均新建版本，不覆盖旧矩阵。验收记录单独存放并引用版本哈希；不要为了更新验收状态改写冻结的矩阵。每个录包同级 `.source.json` 关联车辆档案。每次实验保留完整运行 YAML、输入哈希、代码版本、车辆/标定版本和结果，地图 `build_info.json` 保存同一关联。

## 生成运行配置

WSL 中使用 ROS 开发环境的 Python、PyYAML、NumPy：

```bash
python3 -s scripts/resolve_vehicle_config.py \
  --registry-root /mnt/f/datasets/SANY/vehicles \
  --vehicle-id new_vehicle_20260922 \
  --calibration-id user_provided_20261010_v1 \
  --base-config /path/to/this_site_mapping_base.yaml \
  --output /path/to/experiment/mapping_config.yaml
```

定位配置用本场地定位基础 YAML 再生成一次。脚本要求显式车辆和显式版本，校验归属、SHA-256、话题 ID、主雷达、有限数值、齐次矩阵和旋转矩阵。输出已存在时拒绝覆盖。它只替换 `multi_lidar.extrinsics` 并增加 `calibration_reference`，不会修改融合、时间单位、闭环或重定位门限。`base_config` 必须是本次采集适用的场地/算法配置。

当前约定为行优先 `T_primary_from_lidar`，平移单位 m，即 `p_primary = R * p_lidar + t`；lidar0 为主雷达，其矩阵为单位阵。主雷达原生坐标可能有安装倾角，不能当成车体 x 前/y 左/z 上坐标，也不能直接把雷达外参用作两张地图之间的坐标变换。单位与右手坐标约定可参考 [ROS REP-103](https://github.com/ros-infrastructure/rep/blob/master/rep-0103.rst)。

本次只提供雷达之间外参。`fasterlio.extrinsic_R/T`（LiDAR/IMU）、LiDAR/车体、IMU 单位与轴向、时间偏移、CAN/轮速模型、自车包围盒也具有车辆属性；未获得这些参数前保持已有值，并在来源记录中标注 `inherited_unverified`，不能称为整车参数已全部核实。今后可按明确的字段白名单扩展生成脚本，避免任意覆盖完整基础配置。

地图记录建图车辆标定；定位时使用当前定位车辆的标定。两辆车标定版本不同，并不妨碍使用同一场地地图。不能要求定位车的标定哈希等于建图车哈希。上车前必须确认真实车辆/传感器身份和生成 YAML 的车辆引用；脚本目前无法通过 IP 自动识别硬件。

## 这次数据能检查什么

1. 矩阵合法性、单位、方向、传感器话题绑定及来源是否一致。
2. 完整四雷达两圈建图、闭环约束是否有效、两圈地图是否出现重影。
3. 五组未参与拟合的静止点云，在固定外参下的跨雷达局部平面残差和覆盖率；验收前不能先给每个雷达做 ICP，再用拟合后的误差证明原标定正确。
4. 五个独立定位进程无初始位姿的重定位成功率、定位后有效率、静止漂移。

脚本 `assess_static_lidar_calibration.py` 只测量，不修改标定。用五个静止录包每雷达第 30～39 帧，4～45 m 距离、15 cm 体素、最多 30,000 点、0.5 m 匹配门限和互为最近邻的局部平面配对，对两套固定矩阵作同方法比较。它记录配对数和两个方向的覆盖率。残差仅统计满足配对条件的平面点，植被、遮挡、不同视场和道路坡度会影响结果，不能视作全部点云或绝对精度。

同一段地面可约束法向倾斜和沿法向距离；只有地面不足以检验偏航和沿地面平移。不同雷达看见的地面若有坡度差，拟合平面的法向差也不全是外参误差。无测量真值的静止定位结果只能证明重复性；5 cm 栅格分辨率也不等于 5 cm 定位精度。

## 后续验收采集

先定义定位/感知允许的误差，再制定标定容差。对最远工作距离 R，外参带来的位置误差预算可用保守上界：

```text
error <= ||delta_translation|| + 2 * R * sin(delta_rotation / 2)
```

例如希望 30 m 处外参误差不超过 5 cm，若全部预算留给旋转，容差约 0.0955°；若给平移预留 2 cm，旋转预算约 0.0573°。还要给雷达测距噪声、时间误差和定位误差留预算。这是工程预算示例，不是本批参数的实测误差，也不是行业统一门限。

建议另采一批固定硬质目标：平整地面加两面不平行的墙/标定板，覆盖 5、15、30 m 及各雷达实际重叠视场；固定车姿多次重复，保留一组独立验证录包。优先使用各雷达看见的同一物理目标，剔除植被、自车、移动目标和显著反射异常。记录各对雷达、各距离、各表面方向的 P50/P95 残差、配对数、覆盖率、异常比例，检查六自由度是否受到足够约束。

可把“硬质同一目标上 P50 ≤3 cm、P95 ≤10 cm”作为第一版待评审门限；应结合测距噪声和业务预算正式冻结。不能把这一门限直接套在全场含植被的统计上。关键雷达对没有有效配对或缺少表面方向时应记为“证据不足”，不能忽略后给整组参数判通过。

非重叠视场需要运动约束或共同测量参考；运动手眼标定与独立特征验证可参考 [Das 等，ICRA 2022](https://arxiv.org/abs/2205.07098)。采集应包含左右转弯、不同航向、速度变化和能提供额外旋转约束的正常路段。仅反复沿平面绕圈并不保证六自由度均可观。根据有信息的运动片段检查可观测性，而不是只看录包长短，参考 [Observability-aware online multi-lidar extrinsic calibration](https://arxiv.org/abs/2212.09579)。

时间标定单独检查：静止与运动对照、正反向直行、左右转弯及不同速度。误差随速度/角速度明显增大，应排查时间偏移、点时间单位、IMU 外参和去畸变。扫描起点相差约 10 ms 并不直接证明时钟偏移；本批点有绝对纳秒时间戳。20 ms 融合匹配容差解决帧配对可用性，不能替代时间标定。

最终验收保存版本哈希、原始验证包、场景/距离覆盖、逐雷达指标、重复标定差异、可观测性或独立测量证据及业务功能测试。建议状态依次为“用户提供”“数据功能验证通过”“完整标定验收通过”；没有最后一组证据前不标记整车标定合格。
